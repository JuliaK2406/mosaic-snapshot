# Бэкенд: Google Apps Script

Принимающая сторона страницы. Страница шлёт POST с заявкой на адрес из
`backend.endpoint_url` (файл `content/snapshot.yaml`), скрипт проверяет заявку,
пересчитывает результат, пишет строку в Google-таблицу, отправляет письмо
с результатом через Brevo и, если человек поставил галочку, добавляет его
в список рассылки. Этот файл о том, как бэкенд устроен и как его обновлять.
Клики в Google, Brevo и DNS описаны в инструкции Стаса, не здесь.

## Файлы

| Файл | Что |
| --- | --- |
| `src/validate.js` | проверка заявки и очистка полей |
| `src/limits.js` | решения о дублях и лимитах, числа в начале файла |
| `src/sheet.js` | заголовок таблицы и строка из заявки |
| `src/summary.js` | лист `Summary`: раскладка ячеек и формул, чистая функция |
| `src/email.js` | тема, текст и HTML письма с результатом, уведомление Юлии |
| `src/brevo.js` | тела запросов к Brevo и разбор ответов |
| `src/entry.js` | `doPost`, `doGet`, `setup`, `checkSetup`, `testSubmission` и обвязка |
| `Code.gs` | собранный файл для вставки в Apps Script, генерируется |

`Code.gs` собирается командой `npm run backend` (и внутри `npm run build`) из этих
модулей плюс `src/app/scoring.js` (та же логика результата, что на странице)
и `src/app/submit.js` (та же очистка метки `src`). Первая строка файла говорит,
что он сгенерирован; править его руками нельзя, правки делаются в `src/` и
пересобираются. Тест `test/backend.test.mjs` проверяет, что закоммиченный `Code.gs`
совпадает со свежей сборкой.

Логика написана чистыми функциями в ES-модулях: тесты импортируют их напрямую,
а в Apps Script они попадают склеенными в один файл без `import`. В коде бэкенда
нет ни `?.`, ни `URL`, ни других вещей, которых нет в V8 Apps Script; из `submit.js`
в файл попадают и функции страницы (`calendlyUrl`, `sendPayload`), которые бэкенд
не вызывает, они используют `URL` и `fetch` только внутри себя.

## Как обновить код в Apps Script

1. Поправить модули в `backend/src/`, прогнать `npm test`.
2. `npm run backend` (или `npm run build`), закоммитить `backend/Code.gs`.
3. В редакторе Apps Script заменить содержимое `Code.gs` новым файлом
   (на github.com у файла есть кнопка Copy raw file), сохранить.
4. Deploy, Manage deployments, карандаш, Version: New version, Deploy.
   Адрес веб-приложения при этом не меняется. Новое развёртывание (New deployment)
   делать не нужно: у него был бы другой адрес.

## Свойства скрипта

Project Settings, Script Properties. В репозитории ничего из этого нет.

| Свойство | Что | Обязательно |
| --- | --- | --- |
| `BREVO_API_KEY` | ключ API Brevo | да |
| `BREVO_ENABLED` | `true` или `false`; не задано значит `false` | да |
| `SENDER_NAME` | имя отправителя, `Julia Krylova` | да |
| `SENDER_EMAIL` | адрес отправителя, подтверждённый в Brevo | да |
| `NEWSLETTER_LIST_ID` | номер списка рассылки в Brevo | да |
| `CONTENT_URL` | адрес `content.json` живого сайта | да |
| `REPLY_TO` | адрес для ответов на письмо; не задан: поле не передаётся | нет |
| `TEST_EMAIL` | адрес для `testSubmission`; не подчиняется лимитам на один адрес | нет |
| `NOTIFY_EMAIL` | уведомление о каждой заявке; не задан: выключено | нет |
| `SHEET_ID` | ID таблицы, ставит `setup()` | сам |

Счётчики лимитов тоже живут в Script Properties с ключами `day:…`, `hour:…`,
`emailday:…`; скрипт сам удаляет их через день. Трогать их не нужно.

## Функции для запуска из редактора

- `setup()`: находит таблицу (из которой открыт скрипт, или по `SHEET_ID`), создаёт
  лист `Responses` с заголовками, если их нет, закрепляет первую строку, записывает
  `SHEET_ID`. В старой таблице переименовывает заголовок `Wants to grow` в `Priority`
  на месте (один раз, значения в строках остаются). Потом строит лист `Summary`
  (см. ниже) и ставит его первой вкладкой. Повторный запуск ничего не портит:
  `Responses` не трогается, `Summary` переписывается заново.
- `checkSetup()`: по строке на проверку в журнале: свойства (ключ показан первыми
  четырьмя знаками и длиной), чтение `content.json` и наличие раздела `email`,
  аккаунт Brevo вместе с флагом транзакционной отправки (`relay.enabled`),
  отправители, списки и совпадение `NEWSLETTER_LIST_ID`, атрибуты контактов,
  заголовки таблицы. Последняя строка начинается с `READY` или `NOT READY`.
  Только читает: ни в Brevo, ни в таблицу ничего не пишет.
- `testSubmission()`: прогоняет тестовую заявку (ответы из примера результата,
  имя Test, адрес из `TEST_EMAIL`, метка `test`, без галочки) через тот же путь,
  что настоящие заявки. Итог в журнале и в таблице с заметкой `test submission`.
- `doGet()`: текст `Mosaic Snapshot endpoint` при открытии адреса в браузере.

## Что происходит с заявкой

1. Разбор JSON и проверка полей (`validate.js`). Невалидная заявка: строки нет,
   запись в журнал Executions. Имя теряет управляющие и невидимые символы и ведущие
   `= + - @` (так Google Sheets не прочтёт его как формулу); email, начинающийся
   с этих знаков, невалиден; `submitted_at` принимается только в формате ISO 8601.
   Любой текст, который всё же начинается с `= + - @`, пишется в таблицу с ведущим
   пробелом.
2. Имя со ссылкой или `@`: строка со статусом `rejected`, писем и контакта нет.
3. Результат и средние пересчитываются из ответов по `logic` из `content.json`
   (кеш 10 минут). Присланный результат в заметку, если не совпал.
4. Лимиты (`limits.js`): один адрес (без учёта регистра) не чаще раза в 2 минуты
   и не больше 3 писем в сутки; все вместе не больше 150 писем в час и 280 в сутки,
   уведомления Юлии считаются. Сверх лимита: строка со статусом `rate-limited`,
   письма нет; контакт при галочке всё равно добавляется.
5. Строка в таблицу сразу, со статусами `pending`, под `LockService`. Потом письмо,
   контакт, уведомление; статусы и заметка обновляются в той же строке всегда:
   сетевой сбой Brevo или ошибка внутри даёт `failed` с текстом ошибки в заметке,
   а не вечный `pending`. Если блокировка не досталась за 20 секунд, строка
   пишется без проверки лимитов со статусом `failed` и заметкой `lock`.
6. Письмо: только при `BREVO_ENABLED` равном `true`. Контакт: только при галочке.
   Если Brevo не знает атрибуты, повтор с одним `FIRSTNAME`, потом без атрибутов
   (статус `added-no-attributes`).

Если `content.json` недоступен и кеша нет: результат считается по встроенным
`balanced_gap: 3` и `tie_order: F, P, V`, строка пишется, письмо получает статус
`failed` с заметкой `no content`.

## Таблица

Лист `Responses`, 28 колонок, заголовки на английском. Скрипт пишет по тексту
заголовков, а не по номерам: колонки можно переставлять и добавлять свои справа.
Переименовывать заголовки нельзя, иначе значение не найдёт свою колонку
(`checkSetup` покажет, каких заголовков не хватает). Колонка `Priority` (до 15 октября
2026 называлась `Wants to grow`) хранит выбор на 13-м вопросе как короткое название
части; в payload поле по-прежнему называется `grow`.

Статусы письма: `sent`, `skipped` (отправка выключена), `failed` (ответ Brevo
в заметке), `rate-limited`, `rejected`. Статусы контакта: `added`,
`added-no-attributes`, `no-consent`, `failed`, `skipped`.

## Лист Summary

Первая вкладка таблицы, только формулы, строит `setup()` (`src/summary.js`, функция
`summaryLayout`). Ничего не хранит: считает по `Responses` на лету, строки
с `Source = test` не считает, к колонкам `First name` и `Email` не обращается.
Каждая формула находит свою колонку по тексту заголовка
(`INDEX(Responses!$A$2:$<последняя>,0,MATCH("Заголовок",Responses!$1:$1,0))`),
так что колонки в `Responses` можно переставлять.

Разделы: Responses (всего, с галочкой и без, первая и последняя заявка), Result
(сколько раз каждая часть и Balanced), Priority (выбор на 13-м вопросе, сколько
заявок с фокусом и у скольких приоритет не совпал с результатом), Average by pillar,
Average by question, lowest first (12 пунктов, отсортированы формулой `SORT`
по среднему; в скрытых колонках H:K лежит несортированная таблица, которую читает
`SORT`), By source (`QUERY` по метке, с долей подписавшихся). Названия пунктов
берутся из `content.json` по `CONTENT_URL`; если он недоступен, стоят коды `F1`..`V4`.
После правки текстов вопросов `setup()` надо запустить ещё раз. Форматы: доли `0%`,
средние `0.00`, даты `yyyy-mm-dd hh:mm`; пустая таблица даёт 0 или `-`, не ошибки.

Формулы записываются через `setFormula` в английском синтаксисе: названия функций
по-английски, аргументы через запятую, десятичная точка. Так их принимает Apps Script
при любой локали таблицы, а в самой таблице они показываются уже в локальном
синтаксисе (с точкой с запятой, если локаль нидерландская или русская).

## Письмо

Собирается только из `content.json` и проверенных полей заявки (`email.js`).
Таблицы, inline-стили, Georgia и Arial, сплошные цвета из палитры брифа.
Предпросмотр всех четырёх результатов: `npm run emails` кладёт HTML и текст
в `dist/emails/` и скриншоты в папку скриншотов.
