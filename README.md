# Mosaic of Life Snapshot

Экспресс-оценка по методу Юлии Крыловой: 13 вопросов с телефона, мозаика и результат.
Страница статическая, без фреймворков. Хостинг GitHub Pages, адрес после запуска
`https://mosaic.juliakrylova.com`.

Весь текст страницы лежит в одном файле: `content/snapshot.yaml`. Больше ничего
для правки текста трогать не нужно.

## Для Юлии: как поменять текст

1. Откройте файл на GitHub:
   `https://github.com/JuliaK2406/mosaic-snapshot/blob/main/content/snapshot.yaml`
2. Нажмите карандаш справа сверху (Edit this file).
3. Найдите нужную строку и поменяйте текст после двоеточия. Если текст стоит
   в кавычках, кавычки оставьте, меняйте только то, что внутри.
   Длинные абзацы начинаются со строки `- >-` или `what_it_means: >-`: сам текст
   идёт ниже с отступом, его можно переписывать целиком, отступ в начале строк
   должен остаться таким же.
4. Нажмите зелёную кнопку Commit changes, во всплывшем окне ещё раз Commit changes.
5. Через две-три минуты обновите страницу: изменения уже там. Пока домен не подключён,
   страница живёт по адресу `https://juliak2406.github.io/mosaic-snapshot/`, после
   запуска по адресу `https://mosaic.juliakrylova.com`. Пока сайт собирается,
   во вкладке Actions крутится жёлтый кружок, потом зелёная галочка.

Что можно менять смело: любой текст после двоеточия. Заголовки, абзацы, шаги,
подписи кнопок, названия пунктов и частей мозаики, тексты результатов.

На телефоне и планшете страница одноколоночная, на ноутбуке (от 900 px ширины окна)
двухколоночная: рядом с вопросами собирается мозаика ответов, рядом с формой email
стоит размытая мозаика, на экране результата мозаика и кнопка звонка закреплены слева.
Тексты везде одни и те же, из этого файла.

Две мелочи про вид: подписи разделов результата (`What it means` и соседние) на экране
показаны заглавными буквами, это стиль, в файле их регистр менять не нужно. На первом
экране имя в строке `author_line` выделено жирным, потому что совпадает
с `signature_name`; если имя написать по-разному в двух местах, жирного не будет.

Что лучше не трогать:
- слова до двоеточия (названия полей) и отступы;
- адреса (`site_url`, `calendly`, `main_site`): если менять, то целиком, начиная с `https://`;
- буквы `F`, `P`, `V` в строках `key:` и `tie_order`;
- раздел `logic` (порог сбалансированной мозаики и порядок при ничьей);
- раздел `backend` и строку `published` в `meta`: их включает Стас перед запуском;
- количество: три части по четыре пункта, три варианта в 13-м вопросе, ровно три
  шага в каждом результате.

Если после правки сайт не обновился, значит сборка не прошла: во вкладке Actions
стоит красный крестик, а в нём написано, какое поле сломалось. Сайт при этом
остаётся прежним, ничего не пропало. Напишите Стасу, он поправит.

Если в тексте оставить слово `TODO`, сборка покажет его в списке. Пока
`published: false` это просто напоминание, после запуска такая строка остановит
публикацию.

## Для Стаса

### Собрать и проверить локально

Node 20 стоит через Homebrew как keg-only, в новом терминале сначала:

```bash
export PATH="/opt/homebrew/opt/node@20/bin:$PATH"
```

Дальше из папки репозитория:

```bash
npm ci
npm test
npm run build
npm run serve
```

`npm run serve` поднимает `dist/` на `http://127.0.0.1:4173/` и на
`http://127.0.0.1:4173/mosaic-snapshot/` (путь превью на GitHub Pages, проверка,
что все пути относительные).

Скриншоты всех экранов в папку `../screenshots 01 - каркас/`:

```bash
npm run shots
```

Проверки в браузере (тексты слово в слово из yaml, нет горизонтальной прокрутки
на 360 и 390, шрифты, рамка фокуса, палитра, история, валидация, приватность,
широкий режим на 1024, 1280 и 1440, клавиатура, планшет, короткий экран телефона):

```bash
npm run verify
```

Скриншоты широкого режима, планшета и короткого телефона в папку
`../screenshots 02 - ноутбук/` (внутри `after/` ещё раз телефонный набор):

```bash
npm run shots:wide
```

Попиксельное сравнение двух папок со скриншотами, например телефонного набора
до и после правок (имя файла с `05-email` можно исключить через `--allow`):

```bash
npm run compare -- "../screenshots 02 - ноутбук/before" "../screenshots 02 - ноутбук/after" --only=390- --allow=05-email-errors
```

Клавиатура на экранах вопросов: клавиши 1-9 ставят оценку, 0 ставит 10, на 13-м
вопросе 1, 2 и 3 выбирают карточки, стрелка влево и Backspace это «назад».

Оба скрипта используют Playwright с Chromium из кеша `~/Library/Caches/ms-playwright`.
Версия `playwright` в `package.json` зафиксирована под этот кеш.

### Как устроено

| Файл | Что делает |
| --- | --- |
| `content/snapshot.yaml` | весь текст, единственный файл для правок Юлии |
| `src/check.mjs` | проверка схемы контента и слов TODO, `npm run check` |
| `src/build.mjs` | сборка: yaml, проверка, `dist/` с контентом внутри HTML как JSON |
| `src/app/main.js` | экраны и переходы, история браузера |
| `src/app/scoring.js` | чистые функции: средние, разрывы, фокус, строка про 13-й вопрос |
| `src/app/mosaic.js` | отрисовка мозаики, значка и декоративной мозаики |
| `src/app/submit.js` | сборка payload и отправка; метка `?src=`; ссылка на Calendly с utm |
| `src/app/dom.js` | помощник для создания элементов, без innerHTML |
| `src/styles/tokens.css` | только переменные: цвета, шрифты, размеры |
| `src/styles/app.css` | вёрстка: телефон, а с 900 px ширины окна широкий режим |
| `test/*.test.mjs` | тесты на `node:test`, `npm test` |
| `scripts/serve.mjs` | локальный сервер для `dist/` |
| `scripts/shots.mjs` | скриншоты телефона и десктопа через Playwright |
| `scripts/shots-wide.mjs` | скриншоты широкого режима, планшета и короткого телефона |
| `scripts/compare-shots.mjs` | попиксельное сравнение двух папок со скриншотами |
| `scripts/verify.mjs` | проверки в браузере через Playwright |
| `.github/workflows/deploy.yml` | сборка и публикация на GitHub Pages при пуше в `main` |

Страница не грузит yaml по сети: сборка встраивает контент в `dist/index.html`.
`dist/` в git не коммитится, его собирает Actions.

Логика результата: средний балл части по четырём пунктам, разрыв = 10 минус средний.
Если все три разрыва меньше `logic.balanced_gap`, результат `balanced`. Иначе фокус
это часть с самым большим разрывом, при ничьей порядок из `logic.tie_order`.

### Этапы

1. **Каркас (этот этап).** Все экраны, логика, тесты, скриншоты. Данные никуда
   не отправляются: `backend.endpoint_url` пустой.
2. **Данные.** Google Apps Script принимает POST со страницы, пишет строку
   в Google-таблицу Юлии и передаёт контакт и письмо с результатом в Brevo.
   Адрес скрипта вписывается в `backend.endpoint_url`. Формат payload описан
   в `src/app/submit.js`.
3. **Запуск.** Домен `mosaic.juliakrylova.com` (файл `CNAME` появится только тогда),
   QR-коды с меткой `?src=имя-воркшопа`, кнопка на сайте, уведомление о данных.
   В день запуска `meta.published` ставится в `true`.

### Что делает `published`

Пока `meta.published: false`: в HTML стоит `noindex, nofollow`, в `dist/` лежит
`robots.txt` с `Disallow: /`, на первом экране видна ссылка «See a sample result».
После `true` всё это исчезает, а любое слово `TODO` в контенте останавливает сборку.

### Почему в репозитории нет ключей

Репозиторий публичный, и всё, что в нём лежит, видно всем. Ключ Brevo живёт только
в настройках Apps Script (Script Properties) и в репозиторий не попадает никогда.
Страница знает только адрес скрипта, а он без ключа ничего не даёт.

### Метка воркшопа

Параметр `?src=` в адресе страницы. Остаются только `a-z`, `0-9`, `-`, `_`, не длиннее
40 символов, заглавные буквы приводятся к строчным. Метка уходит в payload и в ссылку
на Calendly как `utm_campaign` (без метки там стоит `direct`).
